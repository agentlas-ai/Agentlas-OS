# 명령어 정상동작 정의서 — 자연어 계약

오너 지시 (2026-08-25): **각 명령어의 정상동작이 무엇인지 자연어로 정의하고,
그것이 실제로 일어나는지가 중요하다.** 게이트·시험·초록불은 이 문장들의 대용품이
아니다. 감사는 이 문서를 채점표로 삼는다: 각 문장이 실측에서 일어나면 PASS,
안 일어나면 그 문장이 곧 결함 제목이다.

작성 규칙:
- "정상동작"은 코드 상태가 아니라 **사용자가 관측하는 결과**로 적는다.
- 각 항목은 (1) 되는 것 (2) 안 되어야 하는 것 (3) 확인 방법 을 가진다.
- 문장이 애매해서 채점 불가면 그 애매함 자체가 이 문서의 결함이다 — 고쳐서 커밋한다.

---

## 공통 — 모든 명령에 적용

1. **로그인 안 된 사람이 쳐도 죽지 않는다.** 로그인이 필요한 명령이면 로그인
   창이 열리고, 창이 안 보이는 경우를 대비해 인증 주소가 반드시 글자로도
   출력된다. (실측 근거: 이 셋이 전부 끊겨 있던 것이 "다운로드는 많은데 가입이
   없다"의 원인 사슬이었다)
2. **자동화가 끈 경우(HEPHAESTUS_AUTO_AUTH=0)와 화면 없는 기계에서는 어떤
   명령도 브라우저를 띄우거나 기다리지 않고 1초 안에 사유와 함께 거절한다.**
3. **명령이 내는 모든 거절에는 푸는 길이 한 문장 들어 있다.** 코드만 있는
   거절은 그 자체가 결함이다. 안내는 CLI 와 MCP 어느 창구로 불러도 똑같이
   실려야 한다.
4. **새로 만든 명령은 업데이트 한 번으로 이미 설치된 모든 기계, 5개 런타임
   전부에 도달한다.** 지워진 명령은 다음 업데이트가 되살린다.
5. **신품 맥(추가 설치 0, 시스템 파이썬만)에서 모든 명령이 첫 실행부터 돈다.**
6. 종료코드는 진실을 말한다: 실패·거절은 0 이 아니다.

## /hep-login · /agentlas-login
- **되는 것**: 치면 브라우저에 로그인 창이 뜨고, 로그인을 마치면 "됐다"는 확인이
  돌아오며, 그 즉시 클라우드가 열린다. 사람이 늦게 로그인해도(10분 안) 성공한다.
- **안 되는 것**: 주소 없이 침묵 대기. 이미 로그인된 상태에서 다시 쳤을 때
  이상한 오류.
- **확인**: 격리 인증홈에서 실행 → stderr 에 주소, 콜백 완료 → authenticated.

## /hep-network (＝/agentlas network)
- **되는 것**: 일을 한 문장으로 주면 로컬+내 클라우드+공개 허브 **세 곳 모두**를
  뒤져 후보 목록을 만들고, 어느 곳이 몇 명을 냈는지 영수증으로 밝힌다. 셋 중
  하나가 죽어 있으면 그 사실을 숨기지 않고 partial 로 말한다.
- **안 되는 것**: 로그인이 죽은 채로 "클라우드에 아무도 없다"로 위장.
  준비(prepare)까지 간 로스터가 실행 없이 조용히 증발.
- **확인**: 세 소스 영수증의 succeeded/failed 를 센다. 로그아웃 상태 대조군.

## /hep-cloud · /hep-hub · /hep-local
- **되는 것**: 각각 정확히 그 한 소스만 본다. cloud 는 로그인한 계정이 소유한
  **전부**(공개 발행 포함)를 본다. 로그아웃 상태의 cloud/hub 요청은
  "물어볼 수 없었다"를 정직하게 말한다.
- **안 되는 것**: 범위 몰래 넓히기/좁히기. 다른 계정 캐시를 물려받기.
- **확인**: 같은 질의를 스코프별로 던져 결과 출처를 대조. 로그아웃 직후 캐시 히트 검사.
  "cloud 는 소유 전부를 본다"는 **개수를 세어 증명하지 않는다** — 셋은 같은
  라우팅을 지나고 부르는 서버 창구 이름만 다르므로(`_SCOPE_TOOL`:
  network→marketplace, cloud→cargo, bookmark→bookmarks), 확인 대상은
  **구조 동일성**이다: 세 스코프가 같은 코드 경로를 타고, cloud 가 그 창구에
  소유 범위를 요구하는 인자를 붙이며, 로컬이 결과를 다시 거르지 않는가.
  범위 결정은 서버가 하고 런타임은 그 답을 그대로 전한다 — 그러므로
  "소유한 것이 검색에서 빠졌다"는 서버 결함이지 이 명령의 결함이 아니다
  (2026-08-25 실측: 공개 발행 284건이 빠져 보이던 것은 서버 가시성 필터였고,
  런타임은 아무것도 안 걸렀다).

## /hep-search (＝검색만)
- **되는 것**: 에이전트를 부르지 않고 후보만 보여준다. 크레딧 소모 0.
- **확인**: 실행 영수증이 없어야 한다.

## /hep-call
- **되는 것**: 이름으로 지목한 에이전트를 정확히 그 릴리스로 준비한다. 없으면
  "없다"를 서버의 정확한 거절 코드 그대로 전한다.
- **안 되는 것**: 비슷한 다른 에이전트로 조용히 대체.

## /hep-build
- **되는 것**: 요청 한 문장에서 설치 가능한 에이전트/팀 패키지가 나온다. 만들어진
  패키지는 검증 게이트를 스스로 통과한다.
- **확인**: 산출 폴더에 contract verify 를 실행.

## /hep-upload
- **되는 것**: 패키지를 올리면 (1) 성공/실패가 사실대로 보고되고 (2) 올라간
  것이 즉시 검색에 잡히고 (3) **검색에 잡힌 것은 준비(다운로드)도 된다.**
  올리기 전 비밀·사적 파일은 기계가 걸러 명단으로 보여준다.
- **안 되는 것**: 올라갔는데 실패라고 보고(과거 실측). 카드만 있고 실물 없는
  등재물이 생기는 것 — 생겼다면 준비 거절이 어느 등재물인지 지목해야 한다.
- **확인**: 업로드→검색→준비 왕복을 실제로 돈다. **이 왕복이 이음새 게이트다.**
  왕복이 끊기는 마디가 곧 결함의 주소다: 올렸는데 검색에 없으면 **서버 색인**,
  검색에 있는데 준비가 거절하면 **서버 저장물**(실측 2026-08-25:
  `object_store_unreadable` — 저장된 패키지 자체가 손상), 준비까지 되는데
  실행이 안 되면 **런타임**. 오너 지적(2026-08-25): 부품마다 검사는 있는데
  부품과 부품 사이를 도는 검사가 없어서, 각 부품이 초록인 채로 사슬이 끊긴다.
  그러므로 이 왕복 하나가 부품 검사 여럿보다 우선한다.

## /hep-storm
- **되는 것**: 목표를 주면 편성→실행→검증을 사람 개입 없이 완주하고, 끝났다는
  말은 실행 영수증(각 단계 증빙)이 있을 때만 한다.
- **안 되는 것**: 준비만 해놓고 "완료" 보고. blocker 가 남았는데 completed.

## /hep-graph
- **되는 것**: 말로 설명한 반복 작업이 저장된 자동화가 되고, list/show/run 이
  각각 목록/내용/실행을 한다. 실행 결과는 관측 증거(파일·URL·영수증)로 판정된다.

## /hep-browser
- **되는 것**: 브라우저가 필요한 일을 전용 브라우저 창에서 수행한다. 저장된
  비밀번호·결제수단은 절대 시드하지 않는다.

## /hep-connect
- **되는 것**: 에이전트/팀을 텔레그램에 연결한다. 5개 런타임 어디서 쳐도 같은
  절차가 나온다(3개 런타임에 명령 자체가 없던 결함은 수리됨 — 재발 감시).

## /hep-orch
- **되는 것**: 오케스트레이터/워커 모델 정책을 보고 바꾼다. 바꾼 값이 다음
  편성의 모델 배정 영수증에 실제로 나타난다.

## /hep-update
- **되는 것**: 한 번 실행으로 런타임과 5개 런타임 어댑터 전부가 최신이 되고,
  빠졌던 파일이 채워진다. 무엇이 갱신/추가/실패인지 개수로 보고한다.
- **안 되는 것**: "current" 라면서 빠진 파일 방치(과거 실측 2회).
- **확인**: 파일 몇 개를 지우고 실행 → 되돌아오는가.

## /agentlas-one
- **되는 것**: 상주 개인 에이전트를 켜고 끈다. 켠 흔적(전역 지침)이 끄면 남지
  않는다.

## /agentlas (디스패처)
- **되는 것**: `/agentlas <동사>` 는 `/hep-<동사>` 와 완전히 같다. 광고하는
  동사 목록과 실제 수용 목록이 항상 일치한다(불일치 2회 실측 — 재발 감시).

## 이 문서의 지위
- 새 명령을 추가하면 **이 문서에 정의부터 쓴다.** 정의 없는 명령은 미완성이다.
- 감사 회차는 이 문서의 문장을 하나씩 실측한다. 문장과 실측이 다르면
  (a) 제품을 고치거나 (b) 오너 승인 하에 문장을 고친다 — 조용한 불일치 금지.
